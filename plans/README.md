## Dependency notes

- 004 remains rejected. Dashboard exports/metrics and Clientes histories require
  complete-history data; pagination needs dedicated summary and history API
  contracts rather than a silent default limit.
- 009 was completed in an earlier repository state, but a later README rewrite
  removed or contradicted its runtime, migration, and deployment corrections.
  Plan 012 supersedes it and adds automated enforcement.
- 012 is complete. Its Node 24 contract and all three GitHub Actions jobs passed
  on the merged PostgreSQL/Render pull requests.
- 003 and 013 are historical MySQL plans and must not be executed. PostgreSQL's
  exclusion constraint changed the concurrency design; plans 016 and 017 are
  their replacements.
- 014's product finding remains valid, but its MySQL implementation is unsafe
  for the current repository. Plan 018 is the PostgreSQL replacement.
- 015 is first because the active pool disables certificate verification and
  application tables live in Supabase's API-exposed `public` schema without an
  explicit RLS boundary.
- 016 is deliberately high risk. It must refuse ambiguous baselines, serialize
  runners, preserve checksums, and run destructive tests only against a guarded
  disposable PostgreSQL database.
- 020 is isolated from the database wave. It uses the smallest compatible
  patches and must not use `npm audit fix --force` or a major toolchain upgrade.

- Tracked `.env` exposure was rejected: `.env` is ignored and not returned by
  `git ls-files`. The local file was not opened.
- Upload validation being MIME-only was rejected: the implementation also checks
  binary image signatures.
- A root npm workspace was rejected as unnecessary for runtime pins and CI.
- An immediate Express major-version migration was rejected because it does not
  address the ranked correctness findings.
- Route lazy loading, payment work, marketplace features, native apps, and
  advanced permissions were deferred behind scheduling, isolation, and
  operational reliability.
- Earlier dependency status was unknown because registry access was unavailable.

  advisory, and three high prototype/tooling advisories; plan 020 owns them.
